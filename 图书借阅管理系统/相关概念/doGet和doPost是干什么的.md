## 一句话总结

- **`doGet`：处理 “查、看、展示” 类请求**
- **`doPost`：处理 “提交、修改、新增” 类请求**

浏览器访问网页时，只会用两种方式发请求：**GET** 或 **POST**

Tomcat 收到后，就会自动调用：

- GET → 执行 `doGet` 方法
- POST → 执行 `doPost` 方法

---

# 一、doGet 干什么？（用来 “查、看”）

### 适用场景

- 打开页面
- 看列表
- 看详情
- 点击链接跳转
- 删除、归还（简单操作也常用 GET）

### 特点

- 数据在地址栏能看到（`?id=1`）
- 可以收藏、刷新
- 不能传大量数据
- 一般**不修改数据库**，只查询

### 你项目里的 doGet 做了什么

```java
case "/list":    展示图书/借阅列表
case "/add":     显示添加表单
case "/edit":    显示编辑表单
case "/delete":  删除图书
case "/return":  归还图书
case "/overdue": 查看逾期
```

**全是 “查看 / 操作展示” 类。**

---

# 二、doPost 干什么？（用来 “提交、修改”）

### 适用场景

- 表单提交（登录、注册、添加图书、借阅图书）
- 上传文件
- 搜索（也常用 POST）
- 新增、修改、删除（安全做法）

### 特点

- 数据**不在地址栏显示**，更安全
- 可以传大量数据
- 刷新会重复提交（所以提交完一般重定向）
- 经常**修改数据库**

### 你项目里的 doPost 做了什么

```java
case "/add":     添加图书
case "/edit":    修改图书
case "/borrow":  借阅图书
case "/search":  搜索
```

**全是 “表单提交、数据修改” 类。**

---

# 三、最简单区分口诀

- **点开页面、点链接 → doGet**
- **填表单点提交 → doPost**

---

# 四、在你的 Servlet 里是怎么分工的？

```java
protected void doGet(...) {
    // 展示页面、查询数据
}

protected void doPost(...) {
    // 处理表单提交、新增、修改
}
```

---

# 五、超简短最终总结

- **doGet = 看数据、展示页面**
- **doPost = 提交表单、改数据**
