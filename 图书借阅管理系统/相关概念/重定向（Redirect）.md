#### 重定向是两次独立请求。
通俗理解可以把这个过程想象成你去银行办理业务的场景：

1. 你（浏览器）走到 A 窗口（服务器的 `/login` 接口）说：“我要办银行卡”；
2. A 窗口柜员看了下，告诉你：“办银行卡要去 B 窗口，你重新去 B 窗口排队”；
3. 你听完后，离开 A 窗口，走到 B 窗口（服务器的 `/main` 接口）重新排队，说：“我要办银行卡”；
4. B 窗口柜员才给你处理业务。

这个过程中，你**找 A 窗口**和**找 B 窗口**是两次完全独立的行为 ——A 窗口不知道你后续找了 B 窗口，B 窗口也不知道你之前找过 A 窗口；对应到 HTTP 中，就是**两次独立的请求**。

### 技术层面的详细拆解（结合登录 Servlet 的例子）

我们以 `response.sendRedirect(request.getContextPath() + "/main")` 为例，一步步看请求过程：

#### 第一步：第一次请求（登录请求）
| 角色   | 行为                                                                                                                                                               |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 浏览器  | 发送 POST 请求到 `http://localhost:8080/library/login`，携带账号密码                                                                                                         |
| 服务器  | 1. 校验账号密码成功；<br><br>2. 创建 Session 并存入 `user` 属性；<br><br>3. 返回 HTTP 响应：状态码 `302 Found` + 响应头 `Location: /library/main`；<br><br>4. 服务器端本次请求的所有数据（如 `request` 对象）销毁 |
| 核心特点 | 服务器只做 “告知跳转地址” 的操作，不处理最终的 `/main` 逻辑                                                                                                                             |

#### 第二步：第二次请求（重定向请求）

| 角色   | 行为                                                                                                                                        |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 浏览器  | 自动识别 302 状态码，读取 `Location` 头的地址，**主动发送新的 GET 请求**到 `http://localhost:8080/library/main`                                                   |
| 服务器  | 接收 `/main` 的 GET 请求，处理主页面逻辑（如查询数据、转发到 main.jsp）                                                                                           |
| 核心特点 | 这是全新的请求 ——<br><br>1. 新请求的 `request` 对象是全新的，和第一次请求的 `request` 无关；<br><br>2. Session 能共享（因为浏览器会携带 `JSESSIONID` Cookie），但 `request` 域的数据完全丢失 |


#### 为什么重定向是两次请求？（对比请求转发）
|维度|重定向（Redirect）|请求转发（Forward）|
|---|---|---|
|发起者|浏览器（服务器返回 302 指令）|服务器内部（浏览器不知情）|
|请求次数|2 次（登录请求 → 主页面请求）|1 次（仅登录请求）|
|request 对象|两次请求的 request 完全独立|全程使用同一个 request 对象|
|数据传递|request 域数据丢失，仅 Session 可共享|request 域数据可正常传递|
|地址栏 URL|变为目标地址（/main）|保持原地址（/login）|

### 实战意义：为什么登录成功要用重定向？

在登录场景中，用重定向而不是请求转发，核心是为了遵循 **Post/Redirect/Get（PRG）设计模式**：
- 问题：如果登录成功后用请求转发到 `/main`，用户刷新页面时，浏览器会重新提交之前的 POST 登录请求，可能导致 “重复登录”“表单重复提交”；
- 解决：重定向是 GET 请求，刷新 `/main` 页面时，只会重新获取主页面，不会重复提交登录表单，避免异常。

### 总结

1. 重定向的 “两次独立请求”：浏览器先发请求到原地址，服务器返回跳转指令，浏览器再发新请求到目标地址，两次请求的 `request` 完全独立；
2. 核心区别：重定向的 `request` 域数据无法传递，仅 Session 可共享；请求转发全程用同一个 `request`，数据可正常传递；
3. 实战场景：登录成功用重定向（避免表单重复提交），登录失败用请求转发（回显错误信息）。
