# 一、请求转发是什么？

**请求转发 = 服务器内部把当前请求交给另一个页面 / Servlet 继续处理**

- 浏览器**只发一次请求**
- URL 地址栏**不会变**
- 可以把数据放在 `request` 里带走
- 整个过程在**服务器内部完成**

你代码里到处都在用：

```java
request.getRequestDispatcher("/WEB-INF/...").forward(request, response);
```



```java
request.getRequestDispatcher("路径").forward(request, response);
```

这一整句 → **就是标准的请求转发**

只写 `getRequestDispatcher("路径")` 不调用 `.forward()`，那不叫转发，只是拿到了 “转发器”。

**必须调用 `.forward()` 才真正执行转发**。

# 二、核心特点（必须记住）

### 1. **一次请求，从头到尾**

浏览器 → Servlet → JSP

**还是同一个 request**

所以你在 Servlet 里放的数据：

```java
request.setAttribute("books", books);
```

在 JSP 里能直接用：

```jsp
${books}
```

### 2. **地址栏不会变**

比如你访问：

```plaintext
/book/list
```

服务器转发到

```plaintext
/WEB-INF/views/book/list.jsp
```

地址栏**仍然是 /book/list**

### 3. **只能转发到项目内部资源**

不能跳百度、不能跳别的网站。

### 4. **WEB-INF 里的页面必须用转发才能访问**

你项目里所有 JSP 都放在 `/WEB-INF`，

**浏览器不能直接访问**，

只能通过 Servlet **转发**进去。

# 三、你代码里的转发例子（结合你的项目）

## 1. 图书列表转发

```java
request.setAttribute("books", books);
request.getRequestDispatcher("/WEB-INF/views/book/list.jsp").forward(request, response);
```

意思：

- 查询到图书列表
- 把数据放进 request
- 转发给 list.jsp 展示
- **地址不变，数据能带走**

## 2. 借阅表单转发

```java
request.setAttribute("readers", readers);
request.setAttribute("books", books);
request.getRequestDispatcher("/WEB-INF/views/borrow/borrow.jsp").forward(request, response);
```

把读者列表、图书列表带到表单页面，让下拉框有数据。

## 3. 错误提示转发

```java
request.setAttribute("error", "图书库存不足");
showBorrowForm(request, response); // 内部就是转发
```

错误信息放在 request，转发回表单页面就能显示红色错误。

# 四、转发 vs 重定向（最容易混淆）

## 请求转发 forward

- 服务器内部跳转
- 1 次请求
- URL**不变**
- 能携带 `request` 数据
- 能访问 WEB-INF
- 适合：**展示数据、列表、表单、错误提示**

## 重定向 sendRedirect

- 浏览器第二次跳转
- 2 次请求
- URL**会变**
- 不能携带 request 数据
- 不能访问 WEB-INF
- 适合：**新增、修改、删除后跳列表**（防止重复提交）

---

# 五、最简单记忆法

### **要带数据 → 转发**

### **不带数据、要换网址 → 重定向**

# 六、一句话总结

**请求转发就是：服务器自己在内部把请求交给下一个页面，能带走数据，地址不变，专门用来展示页面。**
